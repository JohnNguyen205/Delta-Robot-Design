## What this workspace is

This is NOT a software codebase. It is the working folder for a **delta robot mechanical design thesis (đồ án tốt nghiệp)** by an HCMUTE student. The deliverables are SolidWorks CAD models, a BOM, and a thesis document — not compiled code. There is no build, lint, or test command.

The user communicates in **Vietnamese** — respond in Vietnamese unless asked otherwise. Folder names are Vietnamese: `LinhKien` = purchased components, `DoAnThamKhao` = reference theses, `KichThuocThamKhao` = reference dimensions, `MucLuc` = thesis outline.

**Git is broken here**: a `.git` directory exists but is empty, so all git commands fail with "not a git repository" (the session header may still claim "Is a git repository: true" — it is wrong). Do not rely on version control. Backups are done by copying files with suffixes (e.g. `Assem1_backup_20260709.SLDASM`) — always make such a copy before risky changes to CAD files.

**`AGENTS.md` (root) is a stale Codex-tool duplicate of this file** — same content as an older snapshot of this CLAUDE.md (predates the DR-001 3-way split, aluminium base switch, `MoPhong_Ben/MP_BEN_V2`, `.claude/tools/` rename from `.Codex/tools/`). It is not maintained; this CLAUDE.md is the current source of truth — don't cross-check facts against it.

**Backup folder rule (user requirement, 2026-07-12)**: backups of the active design go in `DeltaRobot_Final/Backup/` (NOT the root — root holds only the current active files). **Keep only the single most-recent backup per part/component** in `Backup/`; when making a new backup of a part, delete that part's older backups so the folder never accumulates clutter. Naming stays `<PartName>_backup_YYYYMMDD[_tag].SLD*`; "most-recent" is by file modification time. This applies to `DeltaRobot_Final/` only (the old `Reference/CadTest/Draw_V0/` archive keeps all its backups as-is).

## Working rules (user requirements)

Scope of work in this folder: xây dựng — tính toán thiết kế — mô phỏng 3D — mô phỏng bền (FEA) — tính toán động học — xác định thông số mục tiêu — lựa chọn vật liệu for the delta robot.

1. **Evidence before "done"**: Never report a task as finished without showing concrete results and proof. Only report what has evidence (measured values read back from the model, screenshots, solver output, file paths of generated artifacts, script output). No claims like "đã xong" based on assumption — verify by reading the result back.
2. **Model selection by task type**:
   - **3D simulation, force/FEA simulation, and other heavy tasks** → use model **Fable** (`claude-fable-5`), e.g. `Agent`/`Workflow` calls with `model: "fable"` or running in the main loop on Fable.
   - **Report/thesis writing** → model **Opus** is acceptable (`model: "opus"` for subagents doing report drafting).
3. **Report/thesis writing standards** (đồ án tốt nghiệp quality):
   - Detailed but **selective** calculations — show the load-bearing derivations, not every arithmetic step.
   - Formulas in **standard form** (proper notation, numbered equations, symbols defined, units stated).
   - Include **clear simulation images** (screenshots/renders of CAD, FEA stress/displacement plots, workspace plots) with captions; every simulation claim in the report must be backed by such an image or exported data.
   - **Hard rule (user requirement, 2026-07-24, see `BaoCao/README.md`)**: never cite internal file names (e.g. "theo `KETQUA_BEN.md`", "xem file X") as the justification for a claim in the report body — every number/derivation must stand on its own in the report text (table, formula, or stated boundary condition), and conclusions must be grounded in data shown in that same section, never generic/objective-sounding filler.
4. **Daily progress tracking — `F:\DeltaRobot\TIENDO.md`**: At the end of each working day / session, or whenever the user says the day's work is done ("xong", "làm xong", "hoàn thành"…), update `TIENDO.md`: add today's date section (if missing) listing what was actually accomplished, mark finished items `[x]` (both in the daily log and in the "Tổng quan hạng mục lớn" checklist when a major milestone completes), and leave unfinished work as `[ ]` with a note on where it stopped. Only mark `[x]` for work that meets the evidence rule above.
5. **Quy tắc lưu file theo loại + backup (user requirement, 2026-07-22)**: mỗi loại file có đúng MỘT nơi lưu — không rải rác nơi khác:
   - File CAD (SLDPRT/SLDASM đang hoạt động) → `DeltaRobot_Final/`
   - File mô phỏng bền / FEA → `MoPhong_Ben/MP_BEN_V2/`
   - File bài báo/tài liệu tham khảo → `DoAnThamKhao-Rename/`
   - File mô phỏng động học → `MoPhong_DongHoc/`
   - Bản vẽ gia công (SLDDRW/PDF) → `BanVe_GiaCong/BanVe_ChinhSua_V7/`
   - File báo cáo (docx/md) → `BaoCao/`
   - Mỗi folder trên có 1 subfolder `Backup/` riêng. **Trước khi ghi đè/chỉnh sửa bản gốc trong bất kỳ folder nào ở trên, PHẢI copy bản gốc vào `Backup/` của đúng folder đó trước** (không sửa trực tiếp rồi mới backup — backup luôn đi trước).
6. **Quy trình giao tiếp task (user requirement, 2026-07-22)**: mỗi khi user gõ một task mới trong hội thoại: (a) tóm gọn lại task đó (1-2 câu) trước khi bắt tay vào làm; (b) nếu vừa có task trước đó, báo ngắn gọn đã vừa làm xong gì (cập nhật kết quả/trạng thái) trước khi chuyển sang task mới.

## Driving SolidWorks via COM (the main "tooling" here)

SolidWorks 2023 SP3 is installed at `D:\SOLIDWORKS`. CAD work is done by scripting the running SolidWorks instance over COM from PowerShell. Critical caveats on this machine:

- Normal .NET COM interop (`$obj.Method()`, `InvokeMember`, casting `__ComObject` to interop interfaces) **fails with TYPE_E_ELEMENTNOTFOUND** — the TypeLib registry was repaired but the failure persists per-process/session.
- Always use the raw-IDispatch helper **`.claude/tools/swraw_lib.cs`** (class `SwRaw`); connection example in `.claude/tools/sw_connect_example.ps1`:

```powershell
Add-Type -TypeDefinition (Get-Content 'F:\DeltaRobot\.claude\tools\swraw_lib.cs' -Raw)
$sw = [System.Runtime.InteropServices.Marshal]::GetActiveObject('SldWorks.Application')
[SwRaw]::Invoke0($sw,'RevisionNumber',$false)          # method/property get
[SwRaw]::InvokeN($obj,'Method',@(args))                # method with args
[SwRaw]::InvokeNRefLast($obj,'Method',@(args))         # last arg byref (ActivateDoc3, AddMate5)
[SwRaw]::PutProp($obj,'Visible',$true)                 # property put
[SwRaw]::PutPropRef($comp,'Transform2',$xform)         # PROPERTYPUT alone silently no-ops for objects
```

- Exceptions: `MathUtility` array calls (`CreateTransform`, `CreatePoint`) work with **native** PS dispatch (`$mu.CreateTransform([ref]$a)`); and `IEntity::Select4` needs a compiled C# helper referencing `D:\SOLIDWORKS\api\redist\SolidWorks.Interop.*.dll`.
- Two `SLDWORKS` processes may run; find the real one via ROT moniker `SolidWorks_PID_<pid>`.
- Compiled typed helpers (Add-Type with `-ReferencedAssemblies` on the interop DLLs + `[Reflection.Assembly]::LoadFrom` at runtime) DO work where PS casting fails — prefer them for anything beyond simple property/method calls.
- `IModelDocExtension::GetPackAndGo` crashes SW (RPC_E_SERVERFAULT) on this machine. For save-a-copy-with-renames use `ISldWorks::CopyDocument` + `ISldWorks::ReplaceReferencedDocument` (both work on closed files) instead.

## Editing report PDFs via PyMuPDF (`BaoCao/Bản vẽ gia công/GiaCongCoKhi*.pdf`)

These PDFs are edited directly with `fitz` (PyMuPDF) from Python scripts (not regenerated from source) — inserting/rescaling pages, fixing text, adding tables/images. Traps found doing this (2026-07-24):

- **Vietnamese diacritics vanish unless you register the font first**: `page.insert_text(point, text, fontfile=..., fontsize=...)` silently builds a *simple* (8-bit, Latin-1-only) font, so every tone-mark character (sắc/hỏi/ngã/nặng, U+1EA0–U+1EF9) renders as a missing-glyph box. Fix: `page.insert_font(fontname='FB', fontfile='C:/Windows/Fonts/calibrib.ttf')` once per page, then `page.insert_text(point, text, fontname='FB', fontsize=...)` (no `fontfile=` on the actual insert) — this builds a full Unicode/CID font. Same fix applies to `calibri.ttf`/`calibrii.ttf`/`timesbd.ttf` etc.
- **`get_text('dict')` span `bbox` top-left is NOT the `insert_text` baseline** — the bbox top is `baseline − ascender·fontsize` (Calibri ascender ≈ 0.75). Reusing a scraped `(bbox_x0, bbox_y0)` directly as the insert point shifts the new text up by one ascender-height, which can poke the title above the page border. Compute `baseline_y = bbox_y0 + 0.75 * fontsize` when rebuilding text at a position copied from another page.
- **`add_redact_annot` + `apply_redactions()` must cover the FULL old text bbox**, including trailing characters — search-matching a truncated string (e.g. missing the closing `)` or a hyphenated suffix) leaves old ink behind that double-renders under the new text (looks bold/smeared). Prefer a generous rectangular redact over an exact text-search rect when replacing a short label.
- **Call `insert_font` AFTER `apply_redactions()`, not before** — registering the font then immediately redacting/applying (before any content stream references it) can let the resource get pruned as "unused", and the next `insert_text` on that page throws `Exception: need font file or buffer`.
- **`page.insert_textbox(rect, text, ..., align=fitz.TEXT_ALIGN_JUSTIFY)`** auto-wraps — use it for body paragraphs instead of manually wrapping strings for `insert_text`.
- **Extracted text uses U+00A0 (non-breaking space) instead of U+0020** wherever a custom TTF was registered via `insert_font` — this is a normal PyMuPDF/CID-font quirk, not a defect (visually a normal space, normal width). Any verification script doing `'label' in page.get_text()` must `.replace('\xa0', ' ')` first or the check spuriously fails.
- **Inserting/deleting a page (`doc.new_page(pno=...)`, `doc.delete_page(...)`)** does not auto-renumber anything — every downstream page's printed subtitle (e.g. "TRANG 30 — ...") and footer page-number text, plus any mục lục / table-of-contents entries pointing at those pages, must be found and fixed by hand in the same pass.
- **`Page.show_pdf_page(target_rect, src_doc, src_pno)`** embeds another page's content as a scaled vector form XObject (not a raster) — use this to fit a differently-sized page (e.g. a user-supplied A4 CAD drawing) onto this document's uniform A3-ish canvas without quality loss.
- Always diff `get_text()` page-by-page against a pre-edit copy after any structural change, and visually render (`page.get_pixmap()`) the touched pages — text-level diffing does not catch the bbox/redaction visual artifacts above.
